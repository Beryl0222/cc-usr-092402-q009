# 重点药品报送对账

监管部门对齐药企、园区和地区上报的重点药品生产供应事实。

`fixtures/supply_declaration.json` 保存一条经过脱敏的业务样例，源代码只定义读取这份样例所需的最小合同。后续模块应保持既有标识和时间含义，新增状态必须说明迁移方式。

## 短缺情景与承诺协调（src/shortage/）

在既有申报合同之上增加的协调模块，面向区域性缺口场景：企业按工厂、产线、规格、时间窗申报可追溯产能，地区申报分级需求，检修、质检放行、在途数量、最低保障线一同进入情景比较。

`fixtures/coordination_messages.json` 是一轮完整协调的脱敏消息样例（含一条重复消息），可被 `loadRecord` 读取并逐条回放。

### 模块划分

- `model.js` — 领域常量、窗口/月份工具、不变量校验。时间语义与既有合同一致：`occurred_at` 为带时区 ISO 8601，窗口为闭区间日期，交付与需求按月份对齐。
- `ledger.js` — 事件账本。消息按 `message_id` 去重（重复消息返回原回执、不改变状态）；业务校验失败记入回执但不入账；状态只追加不覆盖。
- `scenario.js` — 情景比较（纯函数）。输出建议分配、缺口与检修影响窗口，仅供协调，不锁定任何可用量，不自动成为行政分配。
- `reconciliation.js` — 轮次对账单，关闭时冻结。
- `views.js` — 企业视图（自身明细+汇总缺口）、专班视图（全局情景与回执）、公开视图（脱敏结论）。

### 核心规则

- **确认才锁定**：承诺提议不占用可用量；企业确认后对应产能即被锁定，同一库存不能再承诺给另一地区（申报与确认两次校验可用量）。
- **迟到修订只重算未锁定部分**：修订量低于已锁定量时，锁定量保持不变，未锁定部分归零并记录异常，等待人工调整。
- **紧急人工调整**：唯一可释放已锁定量的途径，必须附理由，并为每个受影响地区给出替代安排，否则拒绝入账。
- **总量一致**：跨月交付、部分撤回、质检延期、重复消息均保持 `交付明细合计 = 承诺剩余量 = 产能占用合计`，且各批次锁定量不超过当前申报量。
- **履约更正并列留存**：更正作为履约记录的新版本追加，`corrects` 指向原记录，原承诺与原记录不被覆盖；对账口径取各记录链最新版本。
- **对账单**：轮次关闭时冻结，明确哪笔产能支撑哪项承诺、仍有多少缺口、谁尚未确认（提议未确认的承诺及其企业）。

### 状态与迁移

- 既有 `supply_report` 记录（schema_version 1）不受影响；协调消息样例为 schema_version 2，信封沿用 `message_id`/`occurred_at`，业务字段位于 `payload`。
- 承诺状态机：`proposed → confirmed →（部分撤回）→ withdrawn`。履约记录独立成版本链，不改变承诺状态。
- 异常类型：`revision_below_locked`（修订低于锁定量）、`qc_delay_conflicts_lock`（质检延期撞上锁定交付月）、`maintenance_conflicts_lock`（检修窗口撞上锁定交付月）。
- 新增消息类型、承诺状态或异常类型时，只能在 `MESSAGE_TYPES` / `COMMITMENT_STATUS` 等常量末尾追加，并在本文件说明迁移方式；不得修改既有状态含义。
