# 重点药品报送对账

监管部门对齐药企、园区和地区上报的重点药品生产供应事实，并在区域性短缺时进行**仅供协调**的情景试算与承诺协调。

`fixtures/supply_declaration.json` 保存一条经过脱敏的业务样例（schema v1）；`fixtures/coordination_round.json` 是一轮脱敏协调轮次样例（schema v2），由 `scripts/gen_coordination_fixture.mjs` 基于命令层生成。源代码只定义读取样例与执行协调所需的最小合同。

## 数据合同与状态迁移（v1 → v2）

- 沿用 v1 的 `record_id`、`domain="supply_report"`、`occurred_at`（ISO-8601 时刻）、`revision`（正整数，每接收一条事实 +1）与 `source`。
- v2 新增 `round_id`、`as_of_window`（当前协调月份窗，用于判定"未锁定/未来窗口"）与只追加的 `events[]`。
- v1 记录可直接经 `CoordinationRound.fromRecord()` 载入：没有任何协调事实，作为空轮次处理，`round_id` 取 `record_id`。
- **新增状态只能以新事件类型追加**，不得改写既有事件含义或旧事实；履约更正与原承诺并列留存即源于此。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/contracts.js` | v1 最小合同读取（保持不变） |
| `src/ledger.js` | 只追加事件台账：产能（工厂/产线/规格/时间窗）、检修、质检放行/延期、在途、分级需求、承诺、撤回、紧急调整、履约更正；`message_id` 幂等去重；守恒与锁定不变量 |
| `src/coordination.js` | 协调命令构造器与提交（可序列化、可重放） |
| `src/scenarios.js` | 短缺情景试算（只读）：检修扣减、在途预计抵达、最低保障线优先、分级补缺口、建议可追溯到具体产能；输出一律 `advisory=true` |
| `src/reconcile.js` | 对账单：哪笔产能支撑哪项承诺、剩余缺口（实际/计入在途预计两列）、谁尚未确认、履约更正并列、四项守恒检查 |
| `src/views.js` | 三类视图：申报企业（自身明细+汇总缺口）、供应保障专班（全局情景+对账单+回执）、公开页面（仅脱敏结论） |

## 关键业务规则

- 专班的情景计算结果**只供协调**，不会自动成为行政分配；建议经 `commitment_proposed` 落账、企业 `commitment_confirmed` 后才锁定可用量。
- 企业确认后，对应产能即被锁定，不能再分给另一地区（确认时强校验 `锁定量 ≤ 有效产能`）。
- 迟到的产量修订只重算未锁定窗口：修订后产量低于该窗已锁定量时直接拒绝。
- 紧急人工调整必须附理由、操作人，以及**每个受影响地区**的替代安排；可同时调减并以新承诺重配，落地后仍须守恒。
- 部分撤回只允许作用于未来交付窗；已到期的锁定窗必须走紧急调整。
- 跨月交付用月份窗切片表达，切片合计必须等于承诺总量。
- 质检延期只在月份窗之间挪动已登记放行数量；在途满足 `抵达 + 取消 + 剩余 = 申报总量`。
- 重复消息（相同 `message_id`，含原样重发）幂等折叠，不产生任何数量变化。
- 轮次封存（`round_closed`）后不可再追加事件。
